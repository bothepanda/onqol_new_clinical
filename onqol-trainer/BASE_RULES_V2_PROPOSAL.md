# ON QOL — Пересмотр базовых правил (v2) и конвейер дозировок

**Статус:** утверждено автором 19.08.2026 по итогам макет-сравнения на реплее `91ba7206` · детали реализации — на рецензию
**Заменяет:** runtime-границы из `ARCHITECTURE.md` в части ментора и роутера. Не трогает: движок пациента, карточки кейсов, реплеи, тесты мира, governance источников.

---

## 1. Решение

1. Архитектура ментора пересматривается: вместо «детерминированная policy решает, LLM рендерит» — **сильная модель с полным контекстом решает и говорит, детерминированные проверки контролируют выход**.
2. Дозировки **должны присутствовать** в базе знаний. Источник — международные рекомендации + КНФ РК, через существующий governance-конвейер (source registry → rule registry → review → approved_for_training). Позиция «препарат и дозу тренажёр не задаёт» отменяется как постоянная; остаётся только переходным состоянием, пока правило не отрецензировано.

## 2. Базовые правила v2

| # | Правило | Как обеспечивается |
|---|---|---|
| 1 | **Мир детерминирован.** Находки, значения, время, прогрессия — только из карточки кейса. Ментор мир не создаёт. | Движок (без изменений) + leak-детектор `leaksUnrevealedFinding` на выходе ментора |
| 2 | **Числа — только из базы знаний.** Карточка кейса + approved-правила (теперь включая дозовые) лежат у ментора в контексте целиком. Чего в базе нет — ментор обсуждает без цифр и отправляет к формуляру. | Числовой пост-контроль: каждое число в реплике сверяется с картой/правилами/словами резидента |
| 3 | **Диагноз не подтверждается до дебрифа.** | Существующий регекс-контроль (без изменений) |
| 4 | **Safety-стоп детерминирован и срабатывает до исполнения.** Reviewed-правила безопасности параметров — вне юрисдикции модели. | `parameterSafety` (без изменений) |
| 5 | **Отказ проверки → починка, не шаблон.** Один повторный вызов с названной ошибкой; авторский шаблон — только после неудачной починки и для клинических нарушений. | Новый repair-loop в `mentorAgent`; метрика: доля реплик, прошедших с первого раза |

## 3. Что меняется в коде

| Компонент | Судьба |
|---|---|
| `classifyLearnerAdequacy` (регексы адекватности) | Уходит из продакшн-пути. Остаётся как телеметрия для сравнения с решением модели |
| `selectMentorPolicy` (выбор mode/issue/scaffolding) | Решение переходит модели; спека `ONQOL_MENTOR_BEHAVIOR_SPEC` становится системным промптом дословно |
| Шаблоны `mentorBrief` | Последний рубеж (модель недоступна / починка не удалась), не первый ответ на отказ |
| Запрет пересказа revealed facts | Снимается: факты уже на экране резидента. Дословность — только для чисел |
| Запрет гендерного прошедшего времени | Заменяется: форма обращения из настройки сессии или зеркалится из собственных форм резидента («я сделала» → жен.) |
| Роутер как привратник разговора | Остаётся гейтом **исполнения** (что применить к пациенту, что в лог); перестаёт быть гейтом **речи**. Нераспознанный ход получает живой ответ ментора, не «Не распознано» |
| Предусловия (sign-in и т.п.) | Проверяет движок, но по действиям, извлечённым из **всего транскрипта**, а не по совпадению фраз в одном ходе |
| Модель/усилие ментора | Один вызов за ход → сильная модель, нормальный reasoning effort, лимит длины зависит от режима (TEACH при scaffolding 3–4 — до ~2000 знаков) |

## 4. Конвейер дозировок

Доза — это clinical rule нового типа `dosing_rule`, идущий через существующий governance без исключений:

```yaml
rule_id: dosing.cefazolin.surgical_prophylaxis.adult
agent: cefazolin
indication: антибиотикопрофилактика при аппендэктомии
dose: "…"                # дословно из источника при внесении
route: IV
timing: за 60 мин до разреза
adjustments: [масса ≥120 кг, повторное введение при длительной операции]
source_id: bratzler-2013
source_line_verbatim: "…"        # точная строка страницы источника
license_note: свободный доступ (ASHP/IDSA)
kp_rk_status: "КНФ?"             # не сопоставлено, пока не сверено с КНФ
review_status: NEEDS_CLINICAL_REVIEW   # до подписи рецензента NUSOM
runtime_effect: MENTOR_TEACHING только после approved_for_training
```

Порядок: я собираю правила с точными строками источников → статус `NEEDS_CLINICAL_REVIEW` → рецензент подписывает → ментор получает право называть дозу. До подписи ментор ведёт себя как сейчас («сверь с формуляром») — это и есть безопасный переходный режим.

## 5. Верифицированные источники для среза «экстренная абдоминальная хирургия»

Все пять проверены на существование и доступность 19.08.2026. Точные дозовые строки сверяются с PDF при внесении правила (принцип `NEEDS_SOURCE_VERIFICATION` сохраняется).

| Источник | Что даёт | Лицензия / доступ |
|---|---|---|
| **ASHP/IDSA/SIS/SHEA 2013** (Bratzler et al., Clinical practice guidelines for antimicrobial prophylaxis in surgery) | Дозы периоперационной профилактики: цефазолин (взрослая доза, коррекция по массе ≥120 кг, интервалы повторного введения), метронидазол; тайминг до разреза | Свободный PDF на сайтах ASHP и IDSA |
| **WSES/GAIS/SIS-E/WSIS/AAST 2021** (global clinical pathways for intra-abdominal infections, WJES) | Режимы эмпирической антибиотикотерапии при интраабдоминальных инфекциях с дозами; community-acquired vs healthcare-associated | Open access CC BY — без NC-блокера, пригоден и для B2C |
| **WHO AWaRe antibiotic book (2022)** | Дозы для интраабдоминальных инфекций у взрослых и детей, AWaRe-классификация | WHO, CC BY-NC-SA — **NC-оговорка**, тот же монетизационный блокер, что у StatPearls; для пилота ок |
| **FDA label: Ketorolac Tromethamine Injection** | Дозирование кеторолака, отдельная строка для ≥65 лет и почечной дисфункции, максимальная длительность | Public domain (FDA), дословно цитируем |
| **КНФ РК (knf.kz)** — Казахстанский национальный лекарственный формуляр | Локальный слой доз: чем реально располагает больница РК; закрывает пункт «локальный формуляр» из NEXT_SPRINT | Официальный государственный ресурс |

Первая партия правил на рецензию (предлагаю): профилактика при аппендэктомии (цефазолин + метронидазол), анальгезия (кеторолак, включая коррекцию ≥65 — прямой учебный момент из V1-кейсов), стартовая инфузия кристаллоидов.

## 6. План миграции

1. **A/B-харнесс** на фикстурных реплеях (`91ba7206`, `b9d7a831` когда найдётся файл): текущий pipeline против «полный контекст + спека + пост-проверки + одна починка». Метрики: доля реплик без фолбэка, число ходов до прогрессии, субъективная оценка автора.
2. Спека → системный промпт; сборка брифа расширяется до полного контекста (карточка, транскрипт, approved-правила).
3. Repair-loop и режимозависимая длина в `mentorAgent`.
4. Первая партия дозовых правил → рецензия → включение.
5. Контрольная сессия TS-02 по правилам PILOT_TEST_SESSIONS.

## 7. Открытые вопросы (кандидаты в CDR)

1. **Приоритет при расхождении дозы** КНФ РК ↔ международный источник: чему верит ментор и как называет расхождение резиденту? (Паттерн «Свода расхождений КП РК» распространяется на дозы.)
2. **Кто рецензент дозовых правил** — тот же преподаватель NUSOM, что и по кейсу, или отдельно клинический фармаколог?
3. **NC-лицензии** (WHO AWaRe, StatPearls) при переходе к B2C-подписке — заменить источники или получить разрешение (уже помечено в license_review манифеста, дозовый слой добавляет позиций).
4. **Политика «дозы нет в базе»** остаётся навсегда: ментор отправляет к формуляру, никогда не берёт дозу из памяти модели. Подтвердить как постоянное правило №2.
