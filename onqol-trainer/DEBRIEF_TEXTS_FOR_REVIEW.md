**20.08.2026** · выписка из собранного кейса, не из исходных файлов

Резидент читает эти строки в конце кейса, в разделах **«Что сделано»** и
**«Что пропущено или сделано поздно»**. Оценка при этом выключена, числового балла
нет — но текст читается как оценка работы. В ревью CDR-11 он не входил.

Дословно, ничего не отредактировано. Решение по каждой строке — за клиническим владельцем.

## Сколько их на самом деле

В отчёте по FOLLOWUP_CHECKS стояло 73 строки — это счёт по двум исходным файлам.
В собранном кейсе их меньше, и разница существенная:

| | |
|---|---|
| Действий в разборе | **20** |
| Строк «сделано» + «упущено» | **40** |
| Из `cases/acuteAppendicitis.js` | все 20 |
| Из `core/coreActions.js` | **ни одного** — см. ниже |
| Видит один резидент за прогон | ~20 — по одной строке на действие |

Каждое действие даёт **либо** строку «сделано», **либо** строку «упущено», никогда обе:
выполненные попадают в первый раздел, невыполненные во второй. То есть один резидент
прочитает около двадцати строк из сорока, а какие именно — зависит от того, как он вёл пациента.

## Почему core-действий здесь нет

`core/coreActions.js` несёт 18 действий с 36 строками обратной связи — согласие,
оповещение анестезиолога, чек-листы ВОЗ, передача, выписка. В разбор они **не попадают**:
`composeCaseWithCore` кладёт их в `acceptable_alternatives` и `unsafe_actions`, а разбор
строит разделы «сделано» и «упущено» только из `expected_actions`. Список
`acceptable_alternatives` разбор читает — но лишь чтобы найти название действия, не текст.

Действия, чьи 36 строк резидент не увидит:

- `who_time_out`
