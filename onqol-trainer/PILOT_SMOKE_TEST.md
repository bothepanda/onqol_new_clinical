# ON QOL · smoke-тест перед пилотом

Выполняется после `release:check = GO` на точном protected HTTPS URL, который
получат участники. Нужны desktop, телефон, два приватных окна и действующий код.
Любой критический пункт ниже означает остановку запуска.

## 1. Доступ и согласие

- [ ] Без кода и без consent checkbox кнопка «Эталонные условия» неактивна.
- [ ] Неверный код оставляет кнопку неактивной и показывает, что нужен
  действующий код; секрет не появляется в URL, DOM, console или network response.
- [ ] Верный код даёт статус «Серверный контур готов», но без consent кнопка всё
  ещё неактивна.
- [ ] Уведомление явно говорит о provider processing, default retention до
  30 дней, локальных 7 днях и redacted-but-not-anonymous export.
- [ ] После consent можно начать только «Эталонные условия»; real mode и KK
  отключены.
- [ ] Повторить на 390×844: нет горизонтального overflow, control доступен с
  клавиатуры, текст не обрезан.

## 2. Изоляция двух сессий

Начать кейс в окнах A и B.

- [ ] `session_code` и `seed` различаются.
- [ ] На A: `осмотрю живот и соберу анамнез`; на B ничего не меняется.
- [ ] Клиническое время A движется, время B остаётся `00:00` до собственного хода.
- [ ] На B: `соберу анамнез`; ход и mentor response не появляются в A.
- [ ] Новая смена в A получает новый код/seed и пустую рабочую память.

## 3. Router и reasoning guard

- [ ] Ввести: `оценю стабильность, осмотрю живот и проверю беременность`.
  Тренажёр не должен заявить, что участник назвал внематочную беременность или
  сформировал дифференциал.
- [ ] Ввести: `похоже на острый аппендицит, но исключаю внематочную беременность`.
  Обе гипотезы сохраняются без преждевременного «верно/подтверждено».
- [ ] Ввести конкретный escalation threshold: `при АД ниже 90, ЧСС выше 120,
  сатурации ниже 92% или кровотечении эскалирую`. Ответ не должен снова просить
  «назвать конкретные критерии».

## 4. Stable-path completion

Пройти один APP-001–004 кейс обычной клинической речью. Минимальный контрольный
маршрут:

1. оценка стабильности, анамнез и осмотр;
2. обоснованный дифференциал, лаборатория/визуализация и начальное ведение;
3. рабочий диагноз и решение об аппендэктомии;
4. информированное согласие, анестезиолог, операционная команда и локальная
   антибиотикопрофилактика;
5. выбранный доступ, явное начало и завершение аппендэктомии;
6. структурированная передача из операционной;
7. послеоперационная оценка витальных, боли, живота, диуреза, питания и раны;
8. готовность к выписке, лекарства, инструкции, наблюдение и критерии возврата;
9. `конец кейса`.

- [ ] После широкого послеоперационного `контролирую...` фаза переходит в
  послеоперационное наблюдение, а не возвращается к pre-op active observation.
- [ ] На экране нет внутренних id фаз (`data_gathering`, `ward_care` и т. п.).
- [ ] Завершение возможно только после discharge/follow-up endpoint;
  `terminal_status = completed`, score остаётся `null`/`formative_only`.
- [ ] Ответ на `цефазолин 1 г в/в до разреза` не называет локальную дозу ошибкой
  и не подменяет её числом из reference-rule.

## 5. Отчёт и export

- [ ] Создать «Сообщить об ошибке», затем один раз нажать «Скачать JSON».
- [ ] Файл содержит правильный `session_code`, только отчёт этой сессии,
  `raw_learner_text_included: false`,
  `verbatim_transcript_included_after_identifier_scrubbing: true` и telemetry.
- [ ] Поиск по коду второй сессии даёт ноль совпадений.
- [ ] Участнику не предлагают WhatsApp, личную почту или public upload.

## 6. Cohort и эксплуатация

```bash
ONQOL_SMOKE_URL=https://pilot.example.kz \
ONQOL_MAIN_ACCESS_TOKEN='...' \
npm run smoke:cohort
```

- [ ] **8/8 technical router requests** успешны; нет 401/403/429/5xx. Это
  техническая нагрузочная проверка, а не восемь сессий резидентов.
- [ ] Зафиксированы min/median/max latency и provider token usage.
- [ ] Ошибки 401/403/429/5xx не раскрывают prompt, ключ или код доступа.
- [ ] Security headers присутствуют: CSP, HSTS, no-referrer, DENY framing,
  restrictive Permissions-Policy.

Smoke проверяет деплой и механику, но не заменяет manifest approvals и не
валидирует клиническую эффективность продукта.
