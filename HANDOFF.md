## Что нового после V3.1

### Наставник видит содержание рассуждения

Reasoning State хранил факт высказывания. Теперь хранит содержание: какая
гипотеза ведущая, где резидент её поставил, какую назвал опасной, чем
аргументировал за и против, какое исследование меняет план, как он сжал пациента
в одну фразу.

**Инвариант переформулирован.** Было: в брифе нет фактов пациента. Стало: нет
фактов, ПРИНАДЛЕЖАЩИХ КЕЙСУ; собственные слова резидента разрешены. Позиция
`ONQOL_NORTH_STAR.md`. Цитата хранится, только если дословно встречается в
сообщении резидента — пересказ модели отбрасывается поштучно.

Три чекпоинта: наставник 2–3 раза за кейс спрашивает то, что делает рассуждение
видимым. Срабатывают по симулированным минутам, а не по номеру хода.

### Генератор пациентов V3.5

Резидент видит четырёх клинически разных пациентов вместо одной фиксированной.
`buildV35Case({seed})` — вторая фабрика кейсов, не второй движок.
`createV3Case()` не тронут: это регрессионный стенд для сравнения с V2.5.

**Слои разделены.** `APP-001`–`APP-005` — это `case_preset_id`, именованные
комбинации. Отдельно: `phenotype_id`, `morphology`, `population_modifier_ids`,
`trajectory_id`, `resource_profile_id`.

**Физиология принадлежит морфологии.** Фенотип владеет только локализацией.
При одинаковых скрытых входах и physiology sub-seed все физиологические дельты
между фенотипами равны нулю.

**Два потока случайности.** Физиологический ключуется только сидом и не знает,
какой пресет спросил. Презентационный включает пресет, потому что окно обращения
принадлежит фенотипу.

## 3. Что такое V3.1 и зачем

До него движок различал только **выполненные действия**. Два сообщения,
назначающие одни и те же анализы, были для наставника одинаковыми:

```
A: «ОАК, CRP, ХГЧ, УЗИ.»
B: «Рабочий диагноз — аппендицит, но беременность нужно исключить.
    ХГЧ нужен для этого; ОАК и CRP оценивают воспалительный ответ.
    Пациентка стабильна. После результатов решу, достаточно ли данных.»
```

Теперь наставник отвечает им по-разному. А получает «какой клинический вопрос
закрывает это исследование», Б — «дифференциал сформулирован, теперь расставь
приоритеты». Детерминированный слой при этом выполняет одни и те же действия.
Это и есть смысл релиза.

## 4. Архитектура

### Два канала, два разных замка

- **Пациент/среда** (`simulatorAgent.js`) видит карточку кейса и поэтому обязан
  копировать запертый текст.
- **Наставник** (`core/mentorAgent.js`) получает только бриф: типизированные
  ходы, вердикты, авторский текст. Фактов пациента в брифе нет вовсе, поэтому
  слить их архитектурно невозможно.

### `core/reasoningState.js` — что резидент проговорил

21 сигнал: стабильность, рабочий диагноз, дифференциал и его ранжирование,
опасная альтернатива, цель каждого исследования, план и его обоснование,
критерии наблюдения, план Б, переоценка, маршрут, содержание доклада
консультанту.

Накапливается между ходами: сказанное один раз не пропадает оттого, что не
повторено в следующем сообщении.

**Это записи о заявлениях, а не проверенные факты.** Роутеру прямо запрещено
судить о медицинской правильности: он сообщает, что резидент назвал пациента
стабильным, и никогда — стабилен ли пациент на самом деле. Клиническая истина
остаётся детерминированной и принадлежит кейсу.

### `core/mentorHeuristics.js` — 12 правил ядра

Работают на сигналах рассуждения, типах намерений и действиях универсальной
библиотеки. **Ни одного id аппендицита** — это держит тест
`core heuristics name no disease-owned action id`.

Приоритет — по шкале критичности 0–4 из спецификации, не по порядку строк.
Максимум две реплики за ход. Блокирующий стоп затыкает эвристики: когда резидент
лезет оперировать без согласия, ничего другого в этот ход не говорится.

Когда сказать нечего — **наставник молчит**, подсказка системы остаётся.

### `diseases/appendicitis/mentorRules.js` — 3 правила болезни

Обезболивание, содержание доклада старшему, внематочная у пациентки
репродуктивного возраста. Едут вместе с кейсом через `caseData.mentor_rules`.
Ядро их не импортирует.

**Вторая нозология — новый файл + запись в `v3/diseaseModules.js`.** Не правка
ядра, не правка `V25Trainer.jsx`.

### `core/SURGICAL_MENTOR_LOGIC.md` — спецификация

Авторский документ: как наставник думает. Каждая эвристика ссылается на его
раздел через `spec_section`. Машиночитаемая половина — `mentorHeuristics.js`.

## 5. Инварианты V3.1 — не ломать

| Инвариант | Держится тестом |
|---|---|
| Наставник не получает фактов пациента | `the brief carries verdicts, never patient facts` |
| Состояние рассуждения тоже не несёт фактов | `reasoning state reaches the mentor without carrying a patient fact` |
| Наставник не подтверждает диагноз до разбора | `the mentor may not confirm the diagnosis before debrief` |
| Наставник **может** хвалить поведение | `the mentor may affirm professional behaviour` |
| Наставник не приписывает резиденту пол | `the mentor never assigns the learner a gender` |
| Ничто из рассуждения не двигает балл | `nothing produced by Reasoning State is eligible for scoring` |
| Рассуждение логируется отдельно от скоринга | `reasoning is logged beside the turn, never inside scoring events` |
| Поле рассуждения не создаёт действие | `reasoning fields never create a completed action` |
| В ядре нет id болезни | `core heuristics name no disease-owned action id` |
| Правила аппендицита молчат на другой болезни | `appendicitis rules do not fire on another disease` |
| Четыре часа не портят пациента | `four hours reaches the flow checkpoint without touching physiology` |
| Операция без профилактики блокируется до пациента | `appendectomy is blocked before the patient when prophylaxis is missing` |
| Тир «Б» не бывает правильным ответом | `a base-layer fact can never become the scored correct answer` |
| Кейс главнее ядра | `the case wins: core never overwrites a case-owned action` |
| Промпт и схема роутера меняются вместе | `the router schema can actually carry the reasoning the prompt asks for` |

**Отменённый инвариант.** Раньше здесь стояло «тренажёр не немеет никогда».
Отменён сознательно: на вопрос, что лучше — «Что делаешь дальше?» каждый ход или
молчание, ответ был «пусть молчит лучше когда нечего сказать». Это же говорит
раздел 19 спецификации. Осталась узкая гарантия: наставник никогда не *подводит*,
когда ему есть что сказать.

Ещё одно правило без теста: **не выдумывать библиографию.** Где строка не
сверена — стоит `NEEDS_SOURCE_VERIFICATION`. Где сопоставление с КП РК не
делалось — `КП?`, а не `КП−`.

### Технические хвосты

- **Дрейф 1 «бесконечный сбор данных» не детектируется.** Нужен объявленный порог
  «данных достаточно для решения». Считать тесты и звать это shotgun-диагностикой
  прямо запрещено планом; придумывать порог самим — это ровно тот
  неотрецензированный контент, который проект не выпускает.
- **16 состояний пути объявлены и движок не водят.** `temporalPatientModel`
  по-прежнему работает на четырёх грубых фазах. Это самый крупный оставшийся
  кусок V3.5 и главный риск «второго движка».
- **Пути до выписки нет.** Стабильный путь в графе доходит до `complete`,
  в работающем движке — нет.
- **Reasoning snapshots** объявлены по состояниям, но не выпускаются.
- **KZ-текстов нет** — 44 недостающих ключа, контракт и счётчик в `v35/locale.js`.
- **`observation.active` залипает.** Резидент, сказавший «наблюдаем» и потом
  пошедший оперировать, сохраняет флаг. Снять можно, только если роутер научится
  сообщать об отказе от плана. Ущерб ограничен тем, что эвристика говорит раз за
  сессию.
- **Ложное срабатывание матчера: «общий анализ мочи» засчитывается как
  обезболивание.** У `analgesia` в accepted_phrasings стоит `"анальгезия"`,
  матчер режет по префиксу, `анал` находится внутри «анализа». У действия есть
  реальный `score_weight` — резидент получает балл за то, чего не делал.
  Чинить в матчере, не в списке фраз. Задача заводилась отдельно.
- **Без модели наставник заметно суше.** Две реплики за ход склеиваются в два
  отдельных вопроса; с моделью сливаются в одну живую фразу. Детерминированный
  режим — деградация, а не эквивалент.
- У кейса V2.5 версия `2.5.0-alpha.1`, которую схема отвергает. У V3 — `3.0.0`.
- Бренд: старый teal `#16697a` + IBM Plex Mono. PRD требует геометрический
  гротеск на `#265045`. Всё в токенах `:root` в `V25Trainer.css`.
- Персистентность за интерфейсом репозитория, но реализация **только локальная**.

## 9. Как работать с этим репозиторием

- Проверка: `npm test` (164), `npm run lint`, `npm run build`.
- **Живой прогон обязателен.** Три раза подряд зелёные тесты скрывали то, что
  видно на первом же реальном диалоге. Если правишь наставника — прогоняй сессию
  и читай реплики глазами.
- Клинические решения объявляются явно и идут рецензенту. Что нельзя вывести из
  источника — помечается, а не додумывается.
- Ничто из наставника и рассуждения не двигает балл до подписи рецензента.
- Коммиты локальные. `push` — только по прямой просьбе.
- Отправка проекта наружу — только через `npm run pack:safe`.
