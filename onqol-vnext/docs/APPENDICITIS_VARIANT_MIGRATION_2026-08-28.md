# ON QOL vNext — миграция вариантов аппендицита из V3.5

Дата: 2026-08-28  
Донор: `onqol-trainer`, content `3.5.7`  
Результат: варианты перенесены в контролируемый каталог vNext без повышения статуса клинического одобрения.

## Что перенесено

| Preset | Вариант | Статус в vNext |
|---|---|---|
| APP-001 | ранний маловыраженный | `review_pending` |
| APP-002 | классический у женщины репродуктивного возраста | `review_pending` |
| APP-003 | тазовый | `review_pending` |
| APP-004 | ретроцекальный | `development_only` |
| APP-005 | поздний осложнённый | `faculty_preview` |

Перенесены история, локализация боли, данные осмотра, УЗИ, КТ и операционная
истина. Для APP-002 отдельно сохранено ограничение пола и возраста. Для APP-005
сохранён старый development-only физиологический диапазон и только пустой каркас
септической траектории: старые правила ухудшения и ответа на лечение не копировались.

## Что намеренно не перенесено

- отозванная положительная находка при ректальном исследовании тазового варианта;
- старые линейные формулы прогрессирования заболевания;
- ответ на инфузию, антибиотики, вазопрессоры и операцию;
- прежний скоринг и обязательный клинический маршрут;
- неподтверждённые дозы, пороги и safety judgments.

## Были ли варианты «вычитаны»

Частично. В старом пакете есть внутренняя клиническая вычитка и исправления
владельца, но сам disease card имеет `reviewed_internal`,
`independent_review_status: pending` и `production_allowed: false`.

Кроме того, файл
`PILOT_CLINICAL_SIGNOFF_APP001_004_SARINA_TT_2026-08-20.pdf` не является
подписанным допуском: на всех страницах стоит `DRAFT: SIGNATURE REQUIRED`, а
решение, дата и подпись пустые. Поэтому перенос не меняет ни один объект на
`approved_for_training` и не делает варианты learner-selectable.

## Что нужно для активации

1. Подписанный review каждого patient-truth набора либо документа с точным scope APP-001–APP-004.
2. Отдельное подтверждение числовых диапазонов, траекторий и treatment response.
3. Для APP-002/003 — закрытие репродуктивного и гинекологического cross-specialty review.
4. Для APP-005 — самостоятельный review сепсиса, organ dysfunction, реанимации, source control и ОИТ.
5. После этого — повышение конкретных объектов до `approved_for_training`, runtime-тесты и только затем включение выбора кейса в интерфейсе.
