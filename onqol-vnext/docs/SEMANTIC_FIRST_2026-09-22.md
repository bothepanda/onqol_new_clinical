# Смысловой разбор свободной речи — 22.09.2026

Реализован по решению владельца проекта от 21.09.2026: свободная фраза сначала интерпретируется по смыслу; код проверяет команды и исполняет их. Клинические правила, состояние пациента, время и результаты остаются в существующем ядре.

## Что изменилось

- Для `internal_development` приложение по умолчанию выбирает `semantic_first`. Старый `hybrid` доступен явно, `deterministic` служит явным офлайн-режимом. Неизвестное значение настройки и сессии пилота не включают новый режим автоматически.
- Весь свободный текст, включая условия и отрицания, поступает интерпретатору. Словарная команда больше не получает право исполнения только потому, что регулярное выражение её узнало. Пустой ответ, ошибка формата, тайм-аут или недоступность сервиса не возвращают эту догадку в исполнение.
- Быстрый путь оставлен для точных списков из семи сокращений (`ОАК`, `БХАК`, `СРБ`, `ОАМ`, `ХГЧ`, `КТ ОБП`, `УЗИ ОБП`), двух явных управляющих команд и буквального ответа на открытый вопрос о параметре назначения. Контекст вопроса наставника отключает быстрый путь для сокращений.
- Для уже допускаемых смысловых классов отсутствие словарного глагола само по себе не отклоняет новую формулировку. Существующие проверки неизвестных понятий, несовместимых уточнений, неоднозначных категорий и защищённых действий сохранены. Дозы, пути, объёмы и время берутся из слов резидента; болюс теперь корректно распознаётся в кириллице без `\b`.
- Противоречие между кандидатом и сообщением о неоднозначности исключает соответствующий кандидат. Неподтверждённые фрагменты остаются видимыми. Цитата назначения для обсуждения не выполняется независимо от включения наставника.
- Приложение передаёт последний действительно показанный вопрос наставника. Краткий ответ на вопрос о рассуждении не становится назначением исследования.
- Сохраняются исходный ответ сервиса, версия политики, кандидаты, причины отклонения и выполненные команды. Для обсуждений без клинического хода запись находится в `mentor_dialogue[].interpretation`.
- Восстановление сессии использует сохранённый разбор и повторно исполняет команды через ядро. Повторного сетевого вызова или словарного разбора старой свободной фразы нет; несовпадение восстановленного журнала отклоняет восстановление.

## Границы

Это изменение языкового пути и сохранения сессий. Оно не переносит досье `fluids-01` в vNext и не утверждает его клинические данные. Контракты Core Runtime §§48–49, 61–62 и Clinical Governance §§2–4 остаются действующими: язык предлагает действие, содержание и код определяют его результат.

Каталог доступных действий и понятий остаётся обязательным. Словарь также остаётся вспомогательной проверкой известных противоречий и защищённых классов; это не обещание понимания любой формулировки. Рассуждения и оценка компетентности не получили новых полномочий от смыслового интерпретатора. Гранулярность выдачи данных определяется существующими командами и контрактом кейса, а не произвольным текстом ответа сервиса.

Новый режим требует доступного интерпретационного сервиса для свободных фраз. При сбое интерфейс сообщает, что действие не выполнено; не угадывает его. Проверки с фиксированными ответами подтверждают границы исполнения, но не измеряют качество понимания живым сервисом. Новый режим не продвинут в резидентский пилот; RU/KK и независимый набор новых фраз требуют отдельного измерения.

## Как запускать

```sh
npm run dev:semantic
```

Это внутренний режим с новым разбором и разговорным наставником; команда явно выбирает новый разбор даже при сохранённой настройке старого режима в `.env.local`. Для изолированной проверки интерфейса без внешних вызовов:

```sh
npm run test:e2e:semantic
```

Явное возвращение к офлайн-разбору:

```sh
VITE_ONQOL_INTERPRETER=deterministic npm run dev
```

После разрешения внешней проверки:

```sh
npm run semantic:smoke
```

Изменения оставлены в рабочем дереве; ранее существовавшие изменения, удалённый каталог legacy и замороженные материалы измерений не восстанавливались и не переписывались.
