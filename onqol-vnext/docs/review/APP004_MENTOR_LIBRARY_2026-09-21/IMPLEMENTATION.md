# Экспериментальный наставник APP-004 — 21.09.2026

Реализован внутренний RU-диалог по K01–K06 и K12. В едином поле реплики разбирает действующий интерпретатор. Вопросы идут на генерацию и проверку по семи утверждённым карточкам; команды проходят клинический движок. Смешанные реплики сначала выполняют распознанные команды, затем передают вопрос наставнику вместе с показанными результатами. Противоречивое обсуждение назначения требует уточнения без исполнения. Для чистых действий обычный наставник сохранён. K07–K11 не передаются модели.

## Запуск

`npm run dev:mentor -- --port 4177 --strictPort`, затем http://127.0.0.1:4177/ → «Эталонные условия» → единое поле «Действие, вопрос или рассуждение…». Скрипт явно задаёт внутренний режим, отключая флаг пилота для этого запуска. Ключ провайдера читается сервером из существующей конфигурации. По умолчанию эксперимент выключен.

## Механизм

- Сервер выбирает фиксированную библиотеку `src/content/mentor/app004-library.json`, не принимает карточки и системный промпт от клиента.
- Клиент передаёт текущий вопрос, последние 24 сообщения и до 80 уже показанных сообщений среды; каждое ограничено 4000 символами. Усечение отмечается. Скрытое состояние пациента, будущие результаты и полный content bundle не передаются.
- Генерация возвращает типизированные фразы со ссылками на карточки/факты и максимум один вопрос. Структурный контроль проверяет область, статусы, ссылки, длину, отсутствие числового обучения и дословного повторения вопроса. Отдельный вызов того же провайдера проверяет смысловую поддержку и приписывание фактов; отрицательный или некорректный результат даёт резервную реплику.
- Лимит провайдера 30 секунд на вызов; внешний лимит шага 35 секунд, браузера 75 секунд на два вызова. Бюджет наставника отделён от прежних измерений, журнал `.onqol-mentor-budget.json`.
- История обсуждения, показанный ответ, версия/хеш библиотеки, ссылки, сырые ответы провайдера и доступные метаданные сохраняются в session persistence и `mentor_dialogue` JSON-экспорта. Отказ тоже сохраняется. Восстановление не запускает генерацию заново.
- Чистый вопрос не вызывает клинический submit. Распознанное рассуждение сохраняется через STATE_REASONING/ANSWER_MENTOR, чтобы не потерять клинический журнал; это не назначение. В смешанной реплике состояние меняют только команды движка.

## Ограничения и следующий этап

Смысловая проверка тем же провайдером не гарантирует отсутствие неподдержанных утверждений. Сервер доверяет клиентской истории раскрытых фактов; это локальный внутренний эксперимент, не серверно-авторитетная публичная сессия. Единый чат использует существующий детерминированный/гибридный разбор, а не новую универсальную модель маршрутизации. Его ошибки распознавания остаются возможны; неоднозначное подтверждение не достраивает параметры назначения. Долгая история усекается; отдельной долговременной смысловой памяти нет. Полнотекстовый retrieval книг и KK не включены. Утверждение семи карточек не означает допуск к резидентскому пилоту.

Следующий этап — зафиксировать новый набор многоходовых диалогов до оценки и независимо разметить поддержку утверждений, ошибки приписывания действий, повторные вопросы, выход за карточки и полезность ответа. Не использовать эти development-пробы как holdout.

Обновление единого чата: добавлено пять проверок маршрутизации, включая сохранение reasoning, вопросы о лекарствах и смешанные реплики; в браузере дополнительно проверены уточнение без исполнения и ОАК без исполнения обсуждаемой КТ.
