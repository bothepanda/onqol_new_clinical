# APP-004 patient-truth inventory

**Date:** 2026-08-25
**Requested by:** `APP004_CLINICAL_REVIEW_MATRIX_v1.0_2026-08-25` §G1; remediation task §3
**Scope:** every content object that generates a patient fact in APP-004.

---

## Why this exists

The vertical-slice completion report argued that pending phenotype / physiology / history content had to keep generating patients, because otherwise no patient could be generated. The clinical review rejected that as a permanent exception:

> Patient generation is explicitly **Patient Truth** under the governance spec. It cannot be a permanent exception to the strict runtime gate.

This pass does not resolve that by promoting anything. It resolves it by making the exception **visible, enumerated and machine-checked**:

- `core/patient/patientTruthGovernance.js#inventoryPatientTruth` walks the bundle and produces the table below at runtime;
- every non-approved object emits a `SIMULATOR_LIMITATION_NOTED { kind: "patient_truth" }` event at minute 0 of every session;
- `state.session.patientTruthApproved` is `false`, is exported, and is repeated in the debrief as "не предназначен для пилота";
- `scripts/buildContentIndex.mjs` now fails the build if any generating object is missing a provenance field.

**Nothing in the list below is `approved_for_training`. `approved: false` for the whole inventory.**

## Fields NOT generated by any of the above

Listed so the reviewer can see what the case does *not* claim to model:

- appendicolith (matrix I08 — removed from base APP-004);
- incidental findings (matrix I09 — removed from the first slice);

- creatinine, coagulation and blood-group VALUES (qualitative results only; no number is claimed);
- postoperative pain value (matrix PO01 — the state exists, the value does not);
- any complication (matrix T06 — `complications: []`).
